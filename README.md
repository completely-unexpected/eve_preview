# EVE 웹 프로젝트

기존 `eve_project`와 분리된 로컬 프론트엔드·Django 백엔드 프로젝트입니다.

## 로컬 실행 (PowerShell, 저장소 최상위)

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe backend\manage.py migrate
.\.venv\Scripts\python.exe backend\manage.py runserver
```

이미 가상환경·패키지·DB를 준비했다면 마지막 `runserver` 명령만 실행합니다. 가상환경 활성화 스크립트는 필요하지 않습니다.

- 사이트: http://127.0.0.1:8000/
- 관리자: http://127.0.0.1:8000/admin/

관리자 계정이 없다면 `createsuperuser` 명령으로 해당 PC에서 별도 생성합니다. DB와 계정은 GitHub에 저장되지 않습니다.

`dist/index.html`을 파일로 직접 열어 화면을 볼 수도 있지만, 실제 회원 기능은 개발 서버 주소에서만 동작합니다.

## 회원 기능

- 아이디·닉네임·비밀번호·비밀번호 확인으로 회원가입
- 중복 아이디, 약한 비밀번호, 비밀번호 불일치 검증
- 가입 신청 → 관리자 승인 → 로그인, 로그아웃
- 관리자 회원 목록의 승인 대기·승인 완료·이용 정지 상태, 검색·필터
- 선택 회원 일괄 승인·정지·이용 재개 및 변경 이력
- 정지 시 기존 로그인 세션도 다음 요청부터 차단, 관리자 계정 정지 방지
- Django 세션 쿠키로 새로고침 후 로그인 유지
- 상단 닉네임 클릭으로 회원정보 화면 이동 및 입력 오류 안내
- Django 비밀번호 해시 저장 및 CSRF 보호

닉네임은 필수 입력이며 최대 30자입니다. 닉네임 중복은 허용됩니다. 비밀번호 찾기, 이메일 인증, 운영 배포는 아직 구현하지 않았습니다.

API는 `/api/accounts/session/` (GET), `signup/`, `login/`, `logout/` (POST)입니다. POST 입력은 form-urlencoded이며 CSRF 토큰이 필요합니다.

## 화면 기능

메뉴·바로가기, 프로모션 전환, 게임 검색·필터·상세, 이벤트 목록·상세, 카지노 필터, 스포츠 샘플 검색·선택 목록, 뒤로가기·새로고침을 지원합니다. 경기·배당·점수·카지노 분류는 화면 확인용 샘플입니다. 게임 API, 실제 게임 실행, 입출금·베팅·정산은 연결되지 않았습니다.

## 설정·검증

Python 3.14 / Django 6.1.2 / SQLite를 사용합니다. 관리자 언어는 한국어, 서버 시간대는 UTC이며 화면 시계는 서울 시간입니다.

비밀키는 `DJANGO_SECRET_KEY` 환경변수 또는 Git에서 제외한 `backend/.local-secret`에 보관합니다. 로컬 비밀키 파일이 없으면 개발 시 자동 생성합니다. `.venv`, DB, 비밀키는 커밋하지 않습니다.

```powershell
.\.venv\Scripts\python.exe backend\manage.py check
.\.venv\Scripts\python.exe backend\manage.py test accounts
```

회원 테스트는 별도 임시 DB를 사용합니다. 로컬 정적 파일 제공은 DEBUG 모드용입니다. 운영 배포 전에는 정적 파일 제공·HTTPS·배포 설정과 추가 보안 기능을 구성해야 합니다.

## 관리자 회원 관리

새 가입자는 승인 대기 상태로 저장됩니다. 관리자 회원 목록에서 회원을 선택하고 ‘선택한 회원 가입 승인’을 실행하면 로그인할 수 있습니다. 승인된 일반 회원을 정지하거나 정지된 회원의 이용을 재개할 수 있습니다. 관리자·스태프 계정은 이 작업에서 제외됩니다. 기존 활성 회원은 승인 완료, 비활성 회원은 이용 정지로 이관되며 기존 활성 상태는 보존됩니다.

로그인 후 상단 **아이디**를 클릭한 회원정보 화면에서 현재 비밀번호와 새 비밀번호를 입력할 수 있습니다. 변경한 브라우저의 로그인은 유지되고 다른 로그인 세션은 만료됩니다.

로그인 후 상단 **아이디**를 클릭한 회원정보 화면에서 닉네임(최대 30자)을 변경할 수 있습니다. 로그인 아이디와 회원 권한은 변경되지 않습니다.

관리자 페이지의 **공지사항**에서 제목·내용을 작성하고 **게시**를 체크하면 사이트의 공지사항 메뉴에 공개됩니다. 상단 고정과 페이지당 20개 목록을 지원하며, 게시하지 않은 공지는 공개 API에서도 숨겨집니다.

**1:1 문의** 메뉴에서 로그인한 회원이 문의를 작성하고 자신의 문의와 답변만 확인할 수 있습니다. 관리자는 관리자 페이지의 **1:1 문의**에서 답변을 저장합니다. 문의 제목 200자, 내용 10,000자, 목록은 페이지당 20개입니다.

관리자 페이지의 **게임 관리 → 게임**에서 게임명·분류·안내·표시 순서·게시 여부를 관리합니다. 기존 12개 샘플 게임을 처음 한 번 DB에 등록하며 이후 관리자가 수정한 내용을 유지합니다. 게시 해제한 게임은 공개 목록과 상세 API에서 숨겨집니다. 실제 게임 제공업체 API는 아직 연결되지 않았습니다.

관리자 페이지의 **이벤트 관리 → 이벤트**에서 제목·내용·요약·배너 문구·아이콘·게시 여부·표시 순서를 관리합니다. 메인 프로모션 배너와 이벤트 목록·상세 화면에 게시된 이벤트가 반영됩니다. 기존 4개 샘플은 최초 DB 생성 시 등록되며 실제 참여 신청이나 혜택 지급은 제공하지 않습니다.

회원 로그인 API는 같은 접속 IP와 아이디 조합에서 5분 내 5회 실패하면 5분간 제한합니다. 성공하면 실패 기록이 초기화되며, 제한 중에는 남은 시간이 안내됩니다. 제한 기록은 DB에 보관되어 서버 재시작 후에도 유지됩니다. 관리자 로그인에는 이 제한을 적용하지 않습니다.

로그인 후 상단 닉네임를 누르면 **회원정보** 화면에서 아이디·닉네임·레벨·가입일(한국 시간)·이용한도를 확인하고 닉네임과 비밀번호를 변경할 수 있습니다. 로그아웃하면 계정 정보가 숨겨집니다.

관리자 홈의 **관리자 현황 보기**에서 전체 회원(관리자 포함)·승인 대기·이용 정지·전체 문의·답변 대기 문의 수를 확인하고 해당 관리 목록으로 이동할 수 있습니다. 로그인한 활성 관리자에게만 제공하며 각 모델의 조회 권한이 있는 통계만 표시됩니다.

자신의 문의에 읽지 않은 답변이 있으면 상단에 **새 답변 N건**이 표시됩니다. 문의 목록에서는 **새 답변**으로 구분되고 상세 답변을 열면 읽음 처리됩니다. 관리자 답변 수정은 다시 알림을 표시하며 로그인·새로고침·30초 간격·탭 복귀 시 확인합니다. 알림은 사이트 안에서만 표시됩니다.

**게시판**은 누구나 읽고 로그인한 활성 회원이 글을 작성할 수 있습니다. 제목 200자·내용 10,000자, 페이지당 20개이며 작성자의 닉네임이 공개됩니다. 기존 공지사항에서 **게시**와 **상단 고정**을 체크하면 게시판 맨 위에 고정됩니다. 관리자는 **게시판 → 게시글**에서 게시 해제하거나 삭제할 수 있습니다.

게시판은 제목·내용 검색을 지원하고 검색 결과도 20개씩 표시합니다. 페이지 이동과 새로고침에서 검색어가 유지되며 **전체 보기**로 검색을 해제합니다. 고정 공지사항은 검색 결과 위에도 유지됩니다.

게시글 등록 후 같은 회원은 30초 동안 새 글을 등록할 수 없습니다. 서버의 DB 기록을 기준으로 제한하여 새로고침·새 탭·재로그인으로 우회되지 않으며, 제한 시 작성한 내용과 남은 시간이 표시됩니다.

관리자 현황에는 게시판 조회 권한이 있는 관리자에게 전체 게시글 수와 숨김 게시글 수도 표시됩니다. 숨김 게시글 카드는 게시 해제된 글만 필터링한 관리 목록으로 연결됩니다.

**입금·출금** 메뉴에서 회원은 입금·출금 신청과 포인트 전환을 할 수 있습니다. 입금 신청은 관리자 승인 시 보유금액에 반영됩니다. 출금 신청액은 즉시 예약되어 중복 사용을 막고, 승인 시 예약액이 확정 차감되며 거절 시 되돌아옵니다. 관리자는 **보유금액·포인트 → 입금 요청 / 출금 요청**에서 승인·거절하고 **포인트 지급 내역 → 추가**에서 지급합니다. 전환 비율은 1P=1원입니다. 모든 변경은 거래 기록에 남습니다. 은행 송금·입금 확인은 자동화되어 있지 않으며 신청과 승인만 기록합니다.


## 입금 보너스·계좌 요청·이용한도

- **입금 보너스 설정**에서 보너스 이름·설명·지급률(0~100%, 소수 둘째 자리)·지급 대상·표시 순서·사용 여부와 종류별 롤링 퍼센트를 관리합니다. 롤링 빈칸은 ‘이용불가’로 표시됩니다. 초기 보너스는 10%·5%·15%·보너스 없음이며 실제 운영 조건에 맞게 변경할 수 있습니다.
- 회원이 보너스를 선택하고 금액을 입력하면 보너스 지급액과 롤링 조건이 즉시 바뀝니다. 금액은 쉼표로 표시하고 서버에는 정수로 전송합니다. 보너스는 신청 시 서버에서 계산해 조건과 함께 저장하며, 승인 시 원금에 더합니다. 보너스의 1원 미만은 버립니다. 설정 변경·거절·반복 승인으로 기존 신청의 지급액이 바뀌거나 중복 지급되지 않습니다. 지급 대상은 기본 ‘보유금액’이며 관리자가 ‘포인트’로 설정할 수도 있습니다.
- **입금 계좌 설정**에 안내할 계좌를 등록하고 한 계좌만 ‘안내할 계좌’로 지정합니다. 회원의 **입금 계좌 요청**은 **입금 계좌 요청 내역**에 접수됩니다. 관리자가 요청을 열어 안내 계좌를 선택하고 저장하면, 해당 회원이 **계좌 안내 확인**을 누르거나 새로고침해 안내를 확인합니다. 안내 전 계좌 정보는 공개하지 않으며 요청과 안내한 정보는 기록됩니다. 은행 API나 송금은 연결하지 않습니다.
- **레벨별 이용한도**에서 레벨과 싱글·멀티의 최소/최대 베팅, 최대 당첨을 설정합니다. **회원 → 레벨**로 배정하며 회원별 예외 한도를 입력하면 그 회원에게 우선 적용됩니다. 빈칸은 레벨 설정을 따릅니다. 기본은 레벨 1, 최소 10,000원·최대 3,000,000원·최대 당첨 10,000,000원입니다. 회원은 자신의 레벨과 한도를 조회할 수 있고 변경 권한은 없습니다.

게임 실행·베팅 API는 아직 연결되지 않았습니다. 롤링 및 이용한도는 설정·안내·신청 조건 저장 단계이며 실제 이용량 계산, 출금의 롤링 충족 확인, 베팅/당첨 한도 집행은 게임 API와 정산을 연결할 때 구현해야 합니다.

입금 보너스는 참고 이미지의 8개 항목으로 구성합니다. 지급률이 표시되지 않은 신규 입플 보너스와 슬롯 전용 충전보너스는 초기 0%이며 관리자에서 지급률을 지정합니다. 신규회원·첫 입금·슬롯 전용 등의 안내 문구에 대한 실제 자격 판정과 게임 제한 집행은 게임 API 연결 시 추가해야 합니다.


## 출석체크

상단 또는 메뉴의 **출석체크**에서 월별 달력·출석 상태·포인트 지급 내역을 확인하고 당일 출석을 체크합니다. 이전/다음 달을 조회할 수 있습니다. 한국 시간(Asia/Seoul) 자정에 새 출석일이 시작되며 과거 날짜에 출석할 수 없습니다.

기본 조건은 당일 승인된 입금 원금 합계 100,000원 이상, 매일 1,000P, 월 내 7일 연속 출석 40,000P(월 1회), 월 누적 20일 출석 70,000P(월 1회)입니다. 입금 신청일이 아닌 승인일을 기준으로 하며 입금 보너스·포인트 전환은 충전액에 포함하지 않습니다. 연속 출석은 빠진 날과 월 변경 시 새로 시작합니다. 달성일에는 일일 포인트와 보너스를 함께 지급합니다.

**관리자 → 출석체크 → 출석 조건·포인트 설정**에서 사용 여부, 최소 입금액, 일일 포인트, 연속·누적 출석 일수 및 보너스 포인트를 변경합니다. 변경한 조건은 다음 출석 체크부터 적용하며 이미 지급한 포인트는 바꾸지 않습니다. **출석 기록 / 출석 포인트 지급 내역**은 조회 전용입니다. 지급 포인트는 기존 보유 포인트에 합산되어 1P=1원 전환에 사용할 수 있으며 잔액 변경 기록에도 남습니다. 출석일 중복 및 월 보너스 중복 지급을 DB 제약과 트랜잭션으로 막습니다.


## 실제 경기 목록

The Odds API의 무료 sports/events 엔드포인트를 Django 서버에서 호출합니다. 키는 ODDS_API_KEY 환경변수 또는 Git 제외 파일 backend/.local-odds-api-key로 읽고 클라이언트에 전달하지 않습니다. 경기 종목·리그 선택, 팀 검색, 한국 시간 표시, 경기 상세 및 빈 목록/실패 안내를 지원합니다. 종목 목록은 10분, 경기 목록은 2분간 프로세스 캐시를 사용합니다. 배당·점수 엔드포인트는 호출하지 않습니다. 인플레이 메뉴는 시작 시간이 지난 경기만 필터링하며 실제 진행/종료 여부는 아직 연결하지 않았습니다. E-스포츠는 공급업체가 현재 제공하는 리그가 없으면 빈 목록을 안내합니다.


## 전체 스포츠·배당·베팅 카트

스포츠 화면은 종목별 경기 수, Prematch/Inplay, 리그·팀 검색, 시간/리그 정렬, 경기별 배당과 점수, 제공처 선택 및 오른쪽 싱글/멀티 카트를 지원합니다. 승무패·핸디캡·오버언더는 EU 지역 제공처에서 조회합니다. 제공되지 않는 점수/배당은 안내하며 수치를 임의 생성하지 않습니다. 같은 경기에서는 한 선택만 카트에 담고 최대 20경기를 선택합니다. 싱글 금액은 각 경기별로 적용하고 멀티는 한 번 적용합니다. 싱글 당첨금은 경기별 계산을 합산하고 멀티는 배당을 곱합니다. 금액·당첨금은 정수 원 단위로 버림 계산하며 배당 곱셈은 BigInt 고정 소수 연산을 사용합니다. 금액 쉼표, 빠른 금액, MAX(보유금액과 회원 한도 기준), 선택 삭제 및 모두 비우기를 제공합니다. 로그아웃/계정 변경 시 카트를 지웁니다.

카트는 선택과 예상 당첨금 계산 기능입니다. 실제 베팅 접수·잔액 차감·베팅 정산은 아직 연결하지 않았으며 접수 버튼은 비활성화되어 있습니다. 레이(Lay) 시장은 일반 배팅과 계산이 달라 가격만 표시하고 선택하지 못하게 합니다.

외부 조회 결과는 DB에 저장하며 일반 화면 새로고침은 저장본만 읽습니다. 전체 새 조회는 관리자 경기·배당 전체 조회의 작업 또는 `python backend/manage.py sync_sports --force`로 실행합니다. 크레딧이 차감됩니다. 완료된 데이터에 `--force` 없이 명령을 실행하면 재사용하며, 완료하지 못한 조회는 이어서 수행합니다. 완성된 저장본을 전체 갱신할 때 예상 최대 크레딧보다 잔여량이 작으면 기존 자료를 유지하고 갱신하지 않습니다. 실시간 자동 갱신 작업은 등록하지 않았습니다.

관리자는 경기 상세의 **세부 시장 불러오기**로 해당 경기에서 현재 제공되는 추가 시장(전반전·추가 핸디캡·코너·선수 지표 등)을 조회할 수 있습니다. 발견된 시장과 남은 크레딧 범위(최대 100시장)만 요청하며 5분 이내 같은 요청은 재사용합니다. 저장된 세부 시장은 일반 회원도 조회할 수 있습니다. 제공처별 시장 수가 다르므로 제공처를 선택해 확인합니다. 기본 전체 조회에는 72개 리그·882경기가 저장되었고 EPL 한 경기의 추가 시장 38종도 조회했습니다. 최초 전체 조회 후 크레딧 212, 추가 시장 검증 후 173이 남았습니다.
